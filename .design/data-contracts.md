# Data Contracts

Every contract below is implemented twice: as JSON on disk under `content/`, and as a
TypeScript mirror in `app/src/lib/types.ts`. Changing one without the other is the main
source of silent breakage — TypeScript will not catch a wrong field name in JSON because
the payload is cast, not validated, at fetch time.

## File naming

- Lessons: `{NN}-{lesson-slug}.json` — two-digit ordinal prefix, then a lowercase latin slug.
- Rule ids keep the textbook numbering inside the slug (`1A-my-id`, `me-and-my-language`).
- Tests: `day-{NN}.json` with a two-digit ordinal.
- Generated indices: `index.json` inside each `data/{category}/` directory and in
  `content/`.
- `{LEVEL}` is a folder name used verbatim as the level id, including in URLs (`B2+`).

The `id` inside a lesson file **must** equal the slug — the filename minus the `{NN}-`
prefix. `validate_level.py` does not currently assert filename↔id equality, so a mismatch
only surfaces as a `findDataFile` failure in the browser.

## `content/index.json`

A flat, alphabetically sorted JSON array of level-id strings:

```json
["A2", "A2+", "B1", "B2", "B2+"]
```

Regenerated by `content_utils.update_content_index()` from every `content/` subdirectory
that contains a `manifest.json`. It says nothing about lessons or tests.

TypeScript: consumed by `listLevels()` as `string[]`; the `LevelSummary` objects the UI
receives are built in the app, not stored.

## `content/{LEVEL}/manifest.json`

```json
{
  "level": "B2",
  "title": "B2",
  "source": { "sb": "extract/SB.txt", "wb": "extract/WB.txt" },
  "studyOrder": [
    { "type": "rule", "id": "1A-my-id" },
    { "type": "vocabulary", "id": "1A-my-id" },
    { "type": "phrases", "id": "1A-my-id" },
    { "type": "idioms", "id": "1A-my-id" }
  ],
  "testDays": ["day-01", "day-02", "day-03", "day-04", "day-05", "day-06"]
}
```

| Field | Type | Notes |
|---|---|---|
| `level` | `string` | must equal the directory name; `validate_manifest` asserts this |
| `title` | `string` | must equal the level id — the id *is* the display name; asserted by `validate_manifest` |
| `source` | `{ sb?: string, wb?: string }` | both optional; paths are relative to the level directory |
| `studyOrder` | `{ type, id }[]` | **flat** list; derived by `sync_level.py`, must never be hand-maintained |
| `testDays` | `string[]` | day ids without `.json` |

TypeScript mirror (`app/src/lib/types.ts`): `Manifest`, `StudyOrderItem`, `StudyType`.

`studyOrder` is the study spine: for each rule, in rule order, it lists rule → vocabulary →
phrases → idioms, skipping categories with no file for that lesson. The progress key for an
entry is `` `${type}:${id}` `` — see `studyKey()` in `lib/types.ts` and
`parseStudyKey()` for the inverse.

## `content/{LEVEL}/data/{category}/index.json`

A flat, ordered JSON array of **filenames including the ordinal prefix**:

```json
["01-me-and-my-language.json", "02-same-or-different.json", "01-1A-my-id.json"]
```

Order comes from rule `order`. `index.json` itself is excluded from its own listing
(`content_utils.list_data_files`). Written by `sync_level.py`, asserted deep-equal by
`validate_level.py`, and read by the app's `findDataFile()` to map `lessonId` → filename.

## `content/{LEVEL}/data/rules/{NN}-{slug}.json`

```json
{
  "id": "lesson-slug",
  "order": 1,
  "unit": "Unit 1 — Topic",
  "title": "Lesson title",
  "contentMd": "## Grammar topic\n\n### Простая суть\n\n...",
  "examples": ["Example sentence in the target language."]
}
```

| Field | Required by | Notes |
|---|---|---|
| `id` | `validate_rules` | unique across the level; equals the filename slug |
| `order` | `validate_rules` | integer sort key for the whole level; missing values sort as `9999` |
| `unit` | — | free-form grouping label rendered as the unit header |
| `title` | — | lesson title |
| `contentMd` | `validate_rules` | markdown, rendered by `react-markdown` + `remark-gfm` |
| `examples` | — | 2–4 target-language sentences, no translations |

`contentMd` must follow `prompts/rule-generation-style.md` exactly: a `##` heading followed
by the four sections `### Простая суть`, `### Как это работает`, `### Живые примеры`,
`### Лайфхак для запоминания`. Explanations are in the language of instruction; examples are
in the target language. **The section headings are Russian literals in this repo** — they are
hardcoded in `prompts/rule-generation-style.md` and in
`content_utils.build_rule_content_md()`, and changing one without the other breaks the
generated markdown.

TypeScript mirror: `Rule`.

## `content/{LEVEL}/data/{vocabulary,phrases,idioms}/{NN}-{slug}.json`

One shared shape for all three categories:

```json
{
  "lessonId": "lesson-slug",
  "title": "Lesson title — новые слова",
  "items": [
    { "term": "word", "translation": "перевод", "example": "Example sentence." }
  ]
}
```

| Category | Required item key | TypeScript |
|---|---|---|
| `vocabulary` | `term` | `Lexicon` / `LexiconItem` |
| `phrases` | `phrase` | `Lexicon` / `LexiconItem` |
| `idioms` | `idiom` | `Lexicon` / `LexiconItem` |

- `lessonId` is **required** here (rules use `id` instead) and must match an existing rule id.
- `translation` is required on every item; `example` is required for
  `generate_vocab_questions.py` to include the item at all.
- `LexiconItem` in TypeScript models all three keys as optional on one interface
  (`term?`, `phrase?`, `idiom?`), so a malformed item compiles. `validate_level.py` is the
  only guard.
- Translations are in the language of instruction; examples are in the target language.

## `content/{LEVEL}/tests/day-{NN}.json`

A JSON **array** of questions (not an object):

```json
[
  {
    "id": "a3f8c2b91e4d",
    "question": "Which sentence is correct?",
    "options": ["Option A", "Option B", "Option C", "Option D"],
    "correctIndex": 1,
    "explanation": "Brief explanation of the correct answer.",
    "relatedRuleIds": ["lesson-slug"]
  }
]
```

| Field | Contract |
|---|---|
| `id` | `sha256(question + "|" + options.join("|") + "|" + correctIndex)` UTF-8, first 12 hex chars |
| `question` | in the target language |
| `options` | 1–4 entries, target language; array required, length enforced |
| `correctIndex` | `0 <= correctIndex < len(options)` |
| `explanation` | in the target language (a short note in the language of instruction is allowed) |
| `relatedRuleIds` | non-empty list of existing rule ids; drives the test sidebar |

The id is **derived**, never invented. Changing a question, its options, or the correct
index changes the id, which is what deliberately orphans stale `localStorage` progress.
`content_utils.test_id` is the single implementation; `fix_test_ids.py` recomputes it,
`validate_level.py` asserts it, and `assemble_tests.normalize_question` computes it for
grammar sources. The app only reads ids from the JSON — there is no TypeScript
implementation, because the Python pipeline is authoritative.

Reference implementation in Python:

```python
import hashlib

def test_id(question: str, options: list[str], correct_index: int) -> str:
    payload = question + "|" + "|".join(options) + "|" + str(correct_index)
    return hashlib.sha256(payload.encode("utf-8")).hexdigest()[:12]
```

TypeScript mirror: `TestQuestion`.

## Grammar-question sources — `content/{LEVEL}/tests/sources/{lessonId}.json`

Optional input for `assemble_tests.py`: a JSON array of objects with
`{question, options, correctIndex, explanation, relatedRuleIds}` and **no `id`** —
`assemble_tests.normalize_question` computes it via `make_question`. Templates:
`prompts/grammar-questions.example.json`.

## Test plan — `content/{LEVEL}/test_plan.json`

Optional input for `assemble_tests.py`:

```json
{ "questionsPerDay": 20, "days": [["lesson-a", "lesson-b"], ["lesson-c"]] }
```

`days` is a list of lesson groups; each group is distributed `questionsPerDay` questions by
quotient/remainder. Every listed id must exist in `rule_ids(level)` or the run fails.
Template: `prompts/test-plan.example.json`.

## Extract text — `content/{LEVEL}/extract/{SB,WB}.txt`

Not JSON and not validated. Format: page text separated by `\n\n--- PAGE N ---\n\n`. A file
containing **only** page markers means the source PDF had no text layer and
`extract_pdf_ocr.py` must be used instead.

## Browser-side contracts (`localStorage`)

| Key | Serialised shape |
|---|---|
| `language-learning-progress` | `{ state: { levels: { [level]: { completedStudy: string[], completedTests: string[] } } }, version: 1 }` |
| `language-learning-theme` | `{ state: { theme: "light" \| "dark" }, version: 0 }` |

- `completedStudy` entries are `studyKey` strings (`` rule:lesson-slug ``).
- `completedTests` entries are `TestQuestion.id` values.
- Both use the default `zustand/persist` envelope — no `partialize`.
- The progress store has a `migrate` (`LEVEL_RENAMES` in `app/src/store/progressStore.ts`) that
  exists **only** to move a saved level entry when the level id is renamed; `version: 0` predates
  it. See `.design/state-and-storage.md`.
- `app/index.html` reads `language-learning-theme` **before hydration** to set
  `document.documentElement.dataset.theme` and avoid a theme flash.

## Invariants worth preserving

1. `studyOrder` and `data/*/index.json` are **derived**; regenerate with `sync_level.py`
   instead of editing.
2. A level's folder name, `manifest.level` and `manifest.title` are the **same string** — the id
   is the display name. `validate_manifest` asserts all three.
3. Renaming a level id requires a `LEVEL_RENAMES` entry in the progress store; otherwise saved
   progress for that level is orphaned.
4. A lesson without a rule cannot be validated — `validate_lexicon` requires `lessonId` to
   match a known rule.
5. Every `relatedRuleIds` entry must resolve to a real rule id, or the test sidebar renders
   an empty state.
6. `app/public/content/` is a generated mirror. Editing it is pointless — the next `dev`,
   `build`, or `run_app.py` overwrites it. It is gitignored.
7. All JSON is written with `ensure_ascii=False, indent=2` + trailing newline. Preserve that
   formatting when hand-editing to avoid whole-file diffs.
